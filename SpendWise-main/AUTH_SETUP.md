# התחברות, הרשאות ומשקי בית

## מודל החשבונות

כל חשבון `household` מייצג משק בית אחד. נכנסים עם אימייל וסיסמה; `family_size` הוא מספר בני הבית ומשמש לחישוב תקציבים. כל תנועה ויעד נשמרים תחת `user_id` של החשבון. מנהל/ת מערכת הוא חשבון נפרד עם role מסוג `admin`, ורואה רשימת משקי בית וגודל משפחה בלי גישה רגילה לדשבורדים האישיים שלהם.

הרשמה ציבורית תמיד יוצרת `household`. אי אפשר לבחור `admin` בטופס.

## התקנה ראשונית

1. ודאו שמסד `smart_Encomy` והטבלאות קיימים. הפעילו את Flask פעם אחת כדי ש־`create_all` ייצור טבלאות חדשות.
2. הוסיפו את עמודת התפקיד למסד הקיים:

```powershell
sqlcmd -S D403-013 -d smart_Encomy -E -b -i auth_migration.sql
```

3. הפעילו את ה־backend ואת ה־frontend, פתחו את מסך **פתיחת חשבון**, וצרו חשבון אישי עם אימייל, סיסמה באורך 10 תווים לפחות וגודל המשפחה.
4. כדי להגדיר מנהלת, ערכו ב־`auth_migration.sql` את `REPLACE_WITH_MANAGER_EMAIL` לכתובת שנרשמה והריצו שוב את אותה פקודה. לאחר מכן התנתקו והתחברו מחדש. לא משאירים את placeholder כפי שהוא.
5. כל משק בית נוסף נרשם באותו מסך ומקבל חשבון נפרד. במסך המנהלת אפשר לשנות גודל משפחה או לקדם חשבון לתפקיד מנהל.

## נתוני הדגמה

ליצירת נתוני הדמו, הירשמו עם `demo@spendwise.local` ואז הריצו:

```powershell
sqlcmd -S D403-013 -d smart_Encomy -E -b -i seed_demo_spendwise.sql
```

הסקריפט מוסיף נתונים חסרים בלבד ולא מוחק או מחליף תנועות קיימות. הוא מיועד לחשבון הדמו; חשבונות אחרים אינם מקבלים תנועות דמה.

## הגדרות שרת

הגדירו `SPENDWISE_SESSION_SECRET` לערך אקראי ויציב בסביבת שרת קבועה, אחרת restart ינתק sessions. בסביבת HTTPS הגדירו גם `SPENDWISE_COOKIE_SECURE=1`. בפיתוח מקומי אין צורך להגדיר secure cookie.
